# 文献地图 · DeepSeek Harness 插件

从本地论文库生成有原文依据的概念地图，独立深化两个方向，比较可结合的点并保存研究灵感。

[完整用户流程](docs/USER_FLOW.md) · [GitHub 仓库](https://github.com/Qiiii1/literature-map-dsh-plugin)

当前版本：`0.2.0`。目标宿主：本机验证使用的 DeepSeek Harness `0.2.0-rc.2`；插件 API 随宿主升级可能需要适配。

## 使用路径

1. 在 dsh 侧边栏打开「文献地图」。
2. 导入一个本地文件夹，也可逐行粘贴多个 PDF 路径。支持带文字层的 PDF；扫描件需要先做 OCR。
3. 点击「生成地图」。论文会逐篇分析，按概念分组，推荐探索起点。
4. 拖动平移、滚轮缩放、双击或点击「重置」复位。点击概念或关系，右侧联动显示论文、PDF 页序、原文与解释。实线表示论文讨论的关系；普通虚线是尚未验证的 AI 假设。
5. 从概念详情点击「深化这个方向」，或在「探索方向」中新建。每次从当前整张地图独立选取相关概念。
6. 在「结合点」选择两个方向，可补充项目条件。AI 返回具体连接机制、两侧依据、推断、缺口与候选问题；证据不足时可以没有结合点。
7. 返回总览后，符合显示条件的比较结果以金色虚线显示为「结合点」入口；点击预览卡片，再进入完整比较结果。这是导航入口，不代表新的文献证据关系。
8. 在灵感卡片点击「查找类似论文」，生成并修改检索词，比较本地与库外候选的相似点、差异和方法。查看引文、阅读论文后，选择需要的结果加入论文库。
9. 保存灵感后在「已保存」查看，也可回看对应的检索历史。可导出地图、分支、灵感、检索记录和编辑记录为 JSON。

地图搜索按已展示概念的名称和别名筛选；需要查找全部概念时，先点击「展开全部」。建立方向是从现有地图筛选相关概念，不会自动检索库外论文。

可以直接重命名、合并同义概念、移除错误连线，也可用右侧对话修改；两者使用同一份数据并支持撤销。地图有修改或论文有更新时，旧分支保留快照，需要重建后继续比较。

「检查文件更新」会重新检查已导入文件和目录，按内容哈希复用未变化的分析。已删除或无法解析的文件会显示失败。更新地图后，历史用户修改重新应用；找不到目标的修改显示复核提示。

## 安装与模型

依赖 Node.js 22.13+。在本仓库运行：

```sh
npm ci
npm run preview
```

测试服务默认使用 `127.0.0.1:4193`，在 `.local/preview` 内创建独立 dsh profile 和数据文件。完整本机访问链接保存在 `.local/preview/access.json`，按其中的 URL 打开；访问链接包含本地令牌，不要公开分享。

第一次使用测试 profile 时，可在 dsh 模型设置中配置自己的模型。安装到已有 profile 后，插件直接使用 dsh profile 的默认模型与提供方，不需要插件单独保存 API Key；它不会自动跟随另一个聊天中单独选择的模型。运行任务时界面显示当前步骤、进度和取消入口。

打包：

```sh
mkdir -p dist
npm pack --pack-destination dist
```

在实际使用的 dsh profile 中，通过插件管理器安装生成的本地包。CLI 示例（把 `desktop` 换成实际 profile）：

```sh
dsh plugin --profile desktop add /absolute/path/to/literature-map-dsh-plugin-0.2.0.tgz
```

## 数据与证据

- 数据默认写到当前 dsh profile 下 `literature-map/library.json`，可用插件 `dataFile` 配置覆盖。
- 原 PDF 不修改。索引、引文、分析请求与结果、分支和修订记录保存在本机。
- 使用模型会将所需论文片段发送给 dsh 配置的模型提供方；本地存储不等于离线推理。
- 每条引文都校验片段 ID、原文包含关系和源文件版本。该校验确认出处，不能替代人工判断论文是否真的支持关系。
- PDF 页序与论文印刷页码可能不同。原文件内容发生变化后，打开旧证据的原文会要求先检查更新。
- 超长论文超过 110,000 字符输入预算时按全篇分布采样；论文详情显示已分析片段数和总数。
- 任务失败、取消或输出校验失败时保留上一份地图；已完成的单篇抽取缓存可以复用。
- 标错片段号时，只有引文能在同篇已提供材料的唯一页面精确匹配，才会修正定位。无法核验的候选概念和关系会被排除，在论文详情中显示原因；所有概念均未通过时保留旧结果。
- 未指定推理等级时，结构化抽取优先使用模型公开支持的 `off`，地图整合与比较优先使用 `low`；显式设置的推理等级保持不变。实际路由与预算记录在分析日志中。

## 补充论文

只有主动点击「补充相关论文」或灵感中的「检索并比较」才会进行联网论文检索。使用 [Crossref 官方 REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 查询公开题录与可用摘要。

通用「补充相关论文」由 AI 筛选最多三篇、去重并加入库，同时尝试更新地图。旧方向需要重建才能继续比较。

灵感卡片的「查找类似论文」使用单独的预览流程：

- 可自行填写最多三组检索词，也可让 AI 根据灵感的对象、问题和连接机制生成，再编辑。
- 从本地论文筛选候选，同时检索 Crossref；每组最多取得 12 条记录，库外去重后最多保留 18 条。
- 最多提供 16 篇候选材料给模型，输出至多 6 篇比较，区分直接相似、相邻研究和方法参考。长篇本地论文只提供相关片段，并非阅读全文。
- 每篇比较展示相似点、差异与范围、对灵感的启发、待阅读确认内容，以及已核验的逐字引文。有摘要标「仅摘要」；仅题录的记录单列为待阅读线索，不产生内容比较。
- 先预览再选中入库。加入后不自动重建地图，用户可关闭窗口点击「更新地图」。旧方向需要重新建立。
- 检索词、时间、范围、来源失败状态、比较及材料快照保存在对应灵感下，旧库自动兼容。JSON 导出包含检索记录，不包含内部候选全文缓存。

不自动下载出版商全文。不声称检索覆盖整个领域；未找到相似论文不证明选题新颖，内容差异也需要回到摘要或原文复核。

## 原生对话工具

插件注册以下工具供 dsh 对话使用：

- `literature_map_state`：读取论文库、地图与分支。
- `literature_search`：在已导入正文和摘要中做关键词检索，不联网。
- `literature_paper_passages`：读取一篇已导入论文的按页片段。
- `literature_map_edit`：按用户要求修改地图，带版本检查与修订记录。

## 开发验证

```sh
npm run check
npm test
npm run verify:papers -- /absolute/path/to/papers.json
```

论文清单为路径数组，或 `{ "paths": ["/absolute/path/paper.pdf"] }`。验证报告写入 `.local/pdf-verification.json`。

离线 UI 测试使用 `test/fixtures.mjs` 的合成文本和 `test/dsh-adapter.mjs` 的测试适配器。它们不调用外部模型，并在界面中标记 `fixture-test-only`；这些测试材料不放入发行包。真实模型输出质量需要在用户授权的提供方上另行验证。

## 首版边界

单人、本地 PDF、十几篇论文优先。暂不含飞书同步、OCR、自动后台监听、大型语义向量库、完整论文写作和研究新颖性判定。复杂多栏 PDF 的阅读顺序可能存在误差，应在原文中复核关键证据。

具体入口、地图连线含义及当前能力边界见 [用户使用流程](docs/USER_FLOW.md)。
